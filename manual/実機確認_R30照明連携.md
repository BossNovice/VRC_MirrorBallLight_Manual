# 実機確認: R30の照明連携（合成方式・反射方式・Additive受光）

VRChat（PC）で、R30で追加した照明連携の設定が意図どおりに見えるかを確かめる手順です。
**7ケースで20〜30分**を想定しています。

この手順が必要なのは、開発側の自動検証では**VRChatクライアント上の見え方**を確認できないためです。
Unityスタンドアロンの描画検査50シナリオは通っていますが、それは決まった場面のピクセルが
基準と一致することまでで、**実ワールドのVolume配置・LTCGI発光面・Avatar Shader・
ポストプロセスの下でどう見えるか**は分かりません。

対応する追跡項目は [R30-UNEXEC-01](README.md) です。**2026-08-31に7ケースすべてを実施し、解決済みになりました。** 以後の版で確かめ直すときは、結果をそちらと
[バージョン対応表](README.md#動作確認済みの組み合わせ) へ反映してください。

プリセット切替そのものの確認は [実機スモーク確認](実機スモーク確認.md) にあります。

## 準備

1. **VRCLightVolumes と LTCGI を導入したテスト用ワールド**を用意します
   - どちらか一方しか無い環境では、Case 1〜4の比較が成立しません
   - LightVolumeManager と LTCGI Controller をシーンへ置いてください
2. 次の3つを**同時に視界へ入る位置**に置きます
   - 連携版 **不透明** Shaderの壁
   - 連携版 **透過** Shaderのガラス
   - 連携版 **本体ファセット** のミラーボール
3. Controllerの「9. VRCLightVolumes・LTCGI連携」を開きます
4. 各ケースで設定を変えたら、**必ず「対象Materialへ構成を適用・保存」を押します**
   - 押さないとMaterialへ書かれません。**見た目が変わらない原因のほとんどがこれです**

### 観測条件を固定します

**ここを固定しないと、記録を後から比べられません。**

| 項目 | 決めること |
| --- | --- |
| 立ち位置 | 1か所を決め、**全ケースで動かない**。目印を置いてください |
| 視線 | 壁・ガラス・本体が同時に入る向きで固定 |
| 時間帯 | 昼夜が変わるワールドなら、**同じ時刻で固定** |
| 他の光源 | ワールドの他のライトとポストプロセスを**途中で触らない** |
| ミラーボールの電源 | ON。回転速度も変えない |
| AudioLink | Case 6 以外は**音を鳴らさない** |
| スクリーンショット | 各モードで**同じ画角**で1枚。ファイル名にケース番号を入れる |

**明るさの比較は、必ず同じ立ち位置で設定だけを切り替えて行ってください。**
移動してから比べると、Volumeの位置による差と設定による差が混ざります。

## 記録の書き方

各ケースについて、**合格・不合格・未実施**のいずれかを記録します。
**「たぶん大丈夫」は不合格として扱ってください。** 判断がつかなければ、もう一度やり直します。

「合格」は**このケースで見た範囲**の話です。全機能を確認したという意味にはなりません。

## Case 1: 従来の完全加算が、これまでどおり見えること

| | |
| --- | --- |
| **目的** | 既存ワールドの見た目が R30 で変わっていないこと |
| **設定** | 合成方式 = **従来の完全加算**（初期値） |

**操作**

1. 一括プリセットの「従来の完全加算」を押し、適用・保存する
2. 固定した立ち位置から、壁・ガラス・本体を見る
3. スクリーンショットを撮る

**合格条件**

- R29.6以前と**同じ明るさ・同じ色味**に見える
- 白飛び、極端な暗さ、色の転びが無い
- Consoleに赤エラーが出ていない

**このケースが不合格なら、既存ワールドの見た目が変わっています。**
すぐに開発側へ知らせてください。他のケースより優先度が高い項目です。

---

## Case 2: VRCLightVolumesのみ

| | |
| --- | --- |
| **目的** | VRCLightVolumesだけが効き、LTCGIの寄与が消えること |
| **設定** | 合成方式 = **VRCLightVolumesのみ** |

**操作**

1. 一括プリセットの「VRCLightVolumesのみ（主方向反射）」を押し、適用・保存する
2. 同じ立ち位置から見て、Case 1 のスクリーンショットと比べる

**合格条件**

- **LTCGIの発光面が作っていた明るさが減っている**
- Volumeによる面の明るさは残っている
- 真っ黒になっていない

---

## Case 3: LTCGIのみ

| | |
| --- | --- |
| **目的** | LTCGIだけが効き、VRCLightVolumesの寄与が消えること |
| **設定** | 合成方式 = **LTCGIのみ** |

**操作**

1. 一括プリセットの「LTCGIのみ」を押し、適用・保存する
2. 同じ立ち位置から見て、Case 1・Case 2 と比べる

**合格条件**

- **LTCGIの発光面に近い側が明るく、離れた側が暗い**という差が出ている
- Volumeだけで照らされていた場所が暗くなっている
- 真っ黒になっていない

---

## Case 4: 推奨ハイブリッド

| | |
| --- | --- |
| **目的** | 拡散と反射の二重取りが起きず、Case 1 より落ち着いて見えること |
| **設定** | 合成方式 = **ハイブリッド（推奨）** |

**操作**

1. 一括プリセットの「推奨ハイブリッド」を押し、適用・保存する
2. 同じ立ち位置から見て、Case 1 と比べる

**合格条件**

- Case 1 より**明るすぎない**。特にガラスと本体で白飛びが減っている
- 暗くなりすぎてもいない
- **VRCLightVolumesの拡散**とLTCGIの反射の両方が見て取れる

**ハイブリッドではVRCLightVolumesのスペキュラを加算しません。** 設定が
「主方向のみ」や「RGB方向別」でも反射はLTCGI側だけになります。これは仕様です。

---

## Case 5: スペキュラ方式の違い

| | |
| --- | --- |
| **目的** | 主方向のみとRGB方向別が区別でき、負荷の差も体感できること |
| **設定** | 合成方式 = **VRCLightVolumesのみ**（ハイブリッドではスペキュラが乗りません） |

**操作**

1. 反射方式を **なし** にして適用・保存し、見る
2. **主方向のみ** にして適用・保存し、見る
3. **RGB方向別** にして適用・保存し、見る
4. 3つのスクリーンショットを比べる

**合格条件**

- 「なし」より「主方向のみ」の方が、**面のてかりが出ている**
- 「RGB方向別」で、**色の付いたVolumeが複数あるときに反射の色が分かれる**
  （Volumeが1つしか無い、または白のみの場合は差が出なくても構いません。その旨を記録してください）
- ガラスで「RGB方向別」にしたとき、**フレームレートの低下が許容範囲**である

---

## Case 6: AudioLink動作中の明るさ

| | |
| --- | --- |
| **目的** | 音に反応したときに白飛びしないこと |
| **設定** | 合成方式 = **ハイブリッド（推奨）**。AudioLinkを有効にする |

**操作**

1. 音を鳴らし、低音が強い部分で壁・ガラス・本体を見る
2. Case 4 のスクリーンショットと比べる

**合格条件**

- 音のピークで**白飛びしていない**
- Bloomが効きすぎて輪郭が消えていない
- 音を止めると Case 4 の見え方へ戻る

---

## Case 7: Additive Light Volume専用受光

| | |
| --- | --- |
| **目的** | 通常の環境Volumeを含めず、Additive Volumeだけを拾うこと |
| **設定** | 受光方式 = **Additiveのみ** |

**操作**

1. 一括プリセットの「Additive Light Volumeのみ」を押し、適用・保存する
2. **Additive Light Volumeの内側と外側**で見え方を比べる

**合格条件**

- Additive Volumeの内側で明るさが乗っている
- **外側では、通常の環境Volumeの分が乗っていない**
- Consoleに赤エラーが出ていない

**ワールドにAdditive Light Volumeが無い場合、このケースは実施できません。**
「未実施」と、その理由を記録してください。**合格にはしないでください。**

## 結果の反映

1. 上の記録欄を埋めます
2. [バージョン対応表](README.md#動作確認済みの組み合わせ) の R30 の行の「実機目視（PC）」を更新します
   - **全ケース合格でも「済」は代表的なシーンの確認という意味です。** 全機能の網羅ではありません
   - 1つでも不合格があれば「済」にしないでください
3. [R30-UNEXEC-01](README.md) を更新します。全ケースが終わったら項目を閉じ、
   残りがあれば期限と次アクションを書き直します

## 不合格だったときは

再現手順（ケース番号、合成方式、反射方式、受光方式、VRCLightVolumesとLTCGIの版、
スクリーンショット）を添えて、
[Issue](https://github.com/BossNovice/VRC_MirrorBallLight_Manual/issues) へ報告してください。

**Case 1 の不合格は最優先です。** 既存ワールドの見た目が変わっていることになります。
