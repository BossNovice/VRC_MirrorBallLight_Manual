# 過去の版の変更履歴

**このファイルは記録です。現行版の使い方は [manual/README.md](../manual/README.md) を参照してください。**

最新版だけを使う場合、ここを読む必要はありません。古い版のまま運用している場合や、以前の記録と見え方が違う場合の突き合わせに使います。

## 更新の優先度

| 現在お使いの版 | 対応 | 理由 |
| --- | --- | --- |
| R27.1／R27.2／R27.3 | **必ず更新してください** | Import時にUdonSharpのコンパイルが失敗し、プロジェクト内のU#スクリプト全体が壊れます（R27.4で修正） |
| R26／R26.1／R27 | **更新を推奨します** | シード自動フェードでパターンが途中から変化しなくなります（R27.6.3で修正） |
| R25系以前 | 任意 | 上記の不具合は該当しません。Import時間の短縮と機能追加が入ります |

## 出発バージョン別の移行ガイド（R29.4.1へ）

| 移行元 | 注意点 |
| --- | --- |
| R28 | Shader Global共有が有効なControllerが同一シーンに複数あるとBuildを止めるようになります。該当しない場合、動作の変化はありません |
| R27.6.4 | Shader Global共有の書き込みが、値が変わったときだけになります。設定と描画結果は変わりません |
| R27.6〜R27.6.3 | シード自動フェードの修正が入ります。**同じ設定でもパターンの出現順序が従来と変わります**（下記参照）。設定変更は不要です |
| R27.4／R27.5 | 上記に加えて、Import時間が約12分から約1.5分へ短縮されます。Materialの設定と描画結果は変わりません。**廃止したShader Keywordをアニメーションで操作していた場合は移行が必要です**（下記参照） |
| R27.1／R27.2／R27.3 | 上記に加えて、Import時にUdonSharpのコンパイルが失敗する不具合が直ります。**該当版はそのままでは使用できません** |

| R26／R26.1 | 上記に加えて、ライブプリセットへ本体シード設定を保存できるようになります。既存プリセットの動作は変わりません |

| R24以前 | 上記に加えて、壁・ガラスの表面Emissionが追加されます。初期値OFFのため既存の見た目は変わりません |

いずれの場合も、更新後に `Tools > MirrorBall Light > 診断・最適化` の `安全に自動修正` を実行してください。
KeywordとMaterial設定の不一致を検出して揃えます。

## R27.6.3 でパターンの出現順序が変わります

R27.6.3では、シード自動フェードの乱数計算の不具合を修正しました。

修正前は、シード値がShader内部の計算精度を超えて大きくなり、**途中からパターンが
まったく変化しなくなる**状態でした。周期を1〜2秒など短く設定すると顕著ですが、
周期に関わらず発生します。R26以降のすべての版が該当します。

この修正により、**同じ設定でも表示されるパターンの出現順序は従来版と一致しません。**
一方で、**形状の種類・各パラメーターの意味・操作方法・Materialの設定は変わりません。**
目的は「途中で変化しなくなる現象」の解消です。

演出を旧版とフレーム単位で一致させたい場合は、シード値と周期の再調整が必要です。

## 既存のライブプリセットについて（R27.2以前）

R27.2以前に作成したライブプリセットには、本体ファセットのシード設定を保存する項目自体がありません（この項目はR27.3で追加されました）。
そのため、それらのプリセットへ切り替えても本体シード設定はControllerの現在値が維持されます（意図しない上書きを避けるための仕様です）。
プリセットにも本体シード設定を持たせたい場合は、対象プリセット番号を選んで
`現在値を選択プリセットへ保存` を押してください。保存時に `本体シード設定をこのプリセットで指定` が自動でONになります。

## R28.3 不具合の修正

### 時間が経つと光点が増える不具合を修正しました

ワールドを長く開いていると光点が増えていき、最終的に全部点いたままになっていました。
`ランダム点滅を使用` がONのときに起きます。既定の設定では**約2時間で全点灯**していました。

**設定の変更は不要です。** 更新すれば直ります。

### 透過Shaderのアップロード失敗を修正しました

透過（Transparent）Shaderを使うワールドで、アップロードが次のエラーで失敗していました。

```
undeclared identifier 'sampler_CameraDepthTexture'
```

連携版・通常版のどちらも対象です。**深度フェードの設定をONにしているかどうかに関係なく**、
透過Shaderがワールドに含まれていれば失敗します。見え方は変わりません。

### どちらも R27.6 から R28.2 までが対象です

**透過Shaderを使っている場合、またはランダム点滅を使っている場合は更新してください。**

## R28 Shader Global共有の書き込み削減

Shader Global共有（`Udon Global Sharing`）を使っている場合の実行時コストを下げました。
**設定と描画結果は変わりません。**

グローバル共有が有効なとき、Controllerは毎更新（既定30回/秒）で10項目のグローバル値を
書いていました。何か1つでも動いていると全項目を書き直していたため、値が変わらない項目まで
毎回書いていたことになります。直前に書いた値を保持し、**同じ値なら書き込みを省略**します。

外部から上書きされたときに復帰できなくなることを避けるため、**1.5秒ごとにキャッシュを捨てて
全項目を書き直す安全弁**を入れています。

### Shader Global共有は1つのControllerだけで使ってください

グローバル値はワールドで1つの状態を共有する仕組みです。有効なControllerが複数あると
同じ値を奪い合い、最後に書いた側の値だけが反映されます。**複数ControllerでのGlobal共有は
サポート対象外です。**

診断ウィンドウで、Global共有が有効なControllerが複数ある場合に検出して警告します。
1つだけをGlobal共有にして、他はMaterial個別更新へ切り替えてください。

## R27.6 Import時間の短縮とシード計算の修正

### Import時間

新規のVRChatワールドプロジェクトへunitypackageを初回Importしたときの実測です。

| | R27.5まで | R27.6以降 |
| --- | --- | --- |
| unitypackageの初回Import | 810秒 | **128秒** |
| 2回目以降のUnity起動 | 12秒 | 14秒 |

時間の大半はShaderのコンパイルです。R27.6以降も128秒のうち約102秒がShaderのコンパイルで、
これはVRCLightVolumes／LTCGI連携版3本が大部分を占めます。**時間は環境によって変わります。**

### シード自動フェードの修正（R27.6.1／R27.6.2／R27.6.3）

- **R27.6.1** シード自動フェードを停止したとき、パターンがフェード途中で固まる問題を修正
- **R27.6.2** 停止時に前のシードが残り、設定値と違うパターンのままになる問題を修正
- **R27.6.3** シード値が計算精度を超えて、パターンが途中から変化しなくなる問題を修正

### Editorの待ち時間（R27.6.2）

UdonSharp Program Assetが正常な場合でも、Editorのドメインリロードのたびに
プロジェクト全体のUdonSharpコンパイルが1回余分に走っていました。スクリプトの変更、
アセットのImport、Play Modeの出入りのたびに発生していたものです。
実際にProgram Assetを作成または修復したときだけ実行するようにしました。

### 診断ウィンドウの強化（R27.6.2）

- 依存Package（VRCLightVolumes／LTCGI）の有無とバージョンを、診断の最初に表示します
- 未導入の場合は原因と対処を日本語で表示します
- R27.6で廃止したKeywordがMaterialに残っている場合に検出します。Keywordと設定値が
  食い違っている場合は、どちらの状態で動作するかも表示します

## R27.4 Import時のコンパイルエラー修正（重要）

**R27.1〜R27.3をImportすると、UdonSharpのコンパイルが失敗し、プロジェクト内のU#スクリプト
全体が壊れます。** 該当バージョンをお使いの場合は必ず更新してください。

```
[UdonSharp] MirrorBallLightController.cs: Method is not exposed to Udon: 'cycleIndex % seedCycleWrap'
[UdonSharp] U# scripts have compile errors, scene upgrade deferred until script errors are resolved.
```

R27.1で追加したシードの折り返し処理に、Udonへ公開されていない演算を使っていたことが原因です。
VRCLightVolumesのバージョンに関係なく、全環境で発生していました。

あわせて、光点の形状が9種類あるのに対しShaderLabの制約が7組までのため、Material Inspectorで
`Failed to create material drawer Enum with arguments ...` が出ていた問題も修正しました。
形状の選択が日本語のポップアップ（四角／丸／ひし形／十字／テクスチャ／六角形／星／リング／ハート）
になります。R24で形状を9種へ増やした時点からの不具合です。

## R27.3 本体シードのプリセット保存・演出プリセット

R27で追加した本体ファセットのシード設定を、ライブプリセットへ保存できるようになりました。
また、シードフェードを使った既製の演出セットを生成するボタンを追加しました。
どちらも詳細は本ページ後半の「ライブプリセット」を参照してください。

## R27.2 発光NaNガードの修正

R27.1で追加した本体ファセットの発光ガードが、実際にはNaNを検出できていなかった問題を修正しました。
暗所やリアルタイム主光源がない場面で鏡片が黒く潰れる経路への対策が、これで実際に機能します。設定変更は不要です。

## R27 本体ファセットのパターンシード自動フェード

R26で光点形状Atlasへ導入したシード自動フェードを、ミラーボール本体ファセット（鏡片の傾き・色むら・スパークル明滅）へ拡張しました。設定手順は本ページ後半の「ミラーボール本体のファセット表現（R20）」内、R27追記を参照してください。光点Atlas側とは独立した周期で動作するため、両方ONにしても同時に模様替えして見えることはありません。

## R26.1 Atlasシード自動フェード修正

R26.1では、R26のシード自動フェードがGlobal Shader Parameters／GPU回転の静止状態で更新されない問題を修正しました。診断・ビルド前処理によるKeyword同期と、透明背景Atlasの明るさ補間も修正しています。R26で自動フェードを使用している場合はR26.1へ更新してください。ControllerやMaterialの設定はそのまま引き継げます。

## R26 光点形状Atlasシードの自動フェード

複数形状アトラス使用時、`形状配置シード` は従来固定値でした。R26では、周期的に新しいシードへ滑らかに切り替える「自動フェード」を追加しています。設定手順は本ページ後半の「複数形状テクスチャアトラス（R21）」内、R26追記を参照してください。

## R25.2 VRCLightVolumes 3.x法線対応

VRCLightVolumes 3.xの `LightVolumeSH` へワールド法線を渡すよう更新し、法線依存のライト・シャドウ評価が通常面・透過面・本体ファセットへ反映されるようになりました。VRCLightVolumes 2.x環境では従来どおりのAPIを維持するため、Material設定を変更する必要はありません。詳細は本ページ後半の「VRCLightVolumes・LTCGI連携」内、R25.2追記を参照してください。

## 修正済みの不具合（R29系）

現行版では起きません。古い版のまま運用している場合の突き合わせに使います。

### Playモードで「Field for System.Int32 does not exist」が出る

**R29.2で直しました。** R28.1からR29.1までを使っている場合に出ます。

Playモード中にControllerのInspectorを開くと、再描画のたびにこのエラーがConsoleへ出ていました。**Editorのログに出るだけで、ワールドの動作やアップロードには影響しません。** 設定値が失われることもありません。

Error Pause を有効にしていると作業が止まるため、気になる場合はR29.2以降へ更新してください。更新すれば出なくなります。

### プリセットを切り替えると光点が高速で回転する

**R29.3で直しました。** R29.2までが該当します。

`Cookie回転速度` が異なるプリセットへ切り替えたとき、切替中だけ光点が高速で回転していました。同じ原因で `色相送りの速さ`・`ランダム点滅の速さ`・`きらめきの速さ` も高速化していました。

**ワールドに長く居るほどひどくなります。** 実測では、10分後の切替で設定値の約500倍、1時間後で約3000倍の速さで回っていました。

**R29.3では直りきっていませんでした。** ワールドへ入る前にVRChatを長時間起動していた場合、切替のたびにわずかな飛びが残る可能性がありました。R29.3.1で直しています。

R29.3.1以降へ更新すれば、起動時間に関わらず飛びません。設定を変える必要はありません。速度を変えていない限り、見た目は今までと同じです。

### プリセットの項目名が英語で表示される

**R29.3で直しました。** R29.2までが該当します。

プリセットのInspectorだけ項目名が英語で表示され、Controllerと食い違っていました。R29.3以降は56項目すべてが日本語で表示されます。設定値には影響しません。**表示だけの変更です。**

### プリセットで六角形・星・リング・ハートが選べない

**R29.3で直しました。** R29.2までが該当します。

**表示だけの問題ではありませんでした。** プリセットの「光点の形状」は、Controllerの9種類に対し5種類しか選べませんでした。

    選べなかったもの: 六角形 / 星 / リング / ハート

### 消灯するとミラーボール本体が黒くなる

**R29.4で直しました。** R29.3.2までが該当します。

本体は完全な金属で、拡散反射を持たず**映り込みだけで見えます。** 消灯時は映り込み
ごと消えていたため、下地の黒がそのまま出ていました。

R29.4以降は、**映り込みと環境光は電源に関わらず残ります。** 消しているのは
スポットライト由来のきらめきだけです。点灯時の見た目は変わりません。

あわせて Controller に **`消灯時の本体の明るさ`** を追加しました。
`本体ファセットの明るさ倍率` のすぐ下にあります。

| 値 | 消灯時の見え方 |
| --- | --- |
| **1**（既定） | 点灯時と同じ量の映り込みを残します |
| 0.3 | うっすら見える程度 |
| 0 | 映り込みなし |

**0 にしても真っ黒にはなりません。** `暗所での最低表示明るさ`（既定8%）の分は
残ります。**点灯時には影響しません。**

### ボタンを押した人だけ見え方が変わる

**R29.4で直しました。** R29.3.2までが該当します。

ワールドのボタンから「プリセットを即時適用」や「今のプリセットを入れ直す」を
呼んでいる場合、**押した人が所有権を持っていないと、その人の手元だけ状態が
変わっていました。**

変わるのはプリセット番号・回転角・回転の基準時刻です。**押した本人には正しく
見えるため気づきにくく**、その人が後で所有者になると、ズレた値が全員へ配られます。

`プリセットの動作範囲` が `グローバル`（**既定**）のときに起こります。

R29.4以降は、書き込む前に所有権を取り直します。設定を変える必要はありません。

### 長時間まわしていると回転がカクつく

**R29.4で直しました。** R29.3.2までが該当します。

ワールドを長く開けたままにしていると、ミラーボールの回転が段付きになります。
回転角が際限なく積み上がり、数値の精度が足りなくなるためです。

| 回転速度 | 経過 | 回転の刻み |
| --- | --- | --- |
| 10度/秒 | 1週間 | 0.5度 |
| 10度/秒 | 1か月 | 2度 |
| 30度/秒 | 1日 | 0.25度 |
| 30度/秒 | 1週間 | 2度 |

インスタンスが数日続くワールドでは実際に起こります。**R29.4以降は、どれだけ
長く開けたままでも滑らかに回ります。** 設定を変える必要はありません。
