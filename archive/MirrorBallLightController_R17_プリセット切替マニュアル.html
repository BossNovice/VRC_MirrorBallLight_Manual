1. プリセット切替の仕組み

R17では、Controllerの プリセット一覧 に登録された MirrorBallLightPreset を番号で選択します。番号は0から開始します。

一覧上の位置内部番号例
1番目0ゆったりレインボー
2番目1低音パルス
3番目2高速クラブ
スイッチ操作→Custom Event→番号を決定→Preset値をControllerへ適用→Materialを更新
Controller自身をInteractすると切り替わるのは電源です。プリセット切替には、後述するCustom Eventを送るスイッチまたはUdon処理を使用します。

2. 切替前の準備

  1. Controller Inspectorの 2. ライブプリセット を開きます。
  2. ライブプリセットを使用 をONにします。
  3. 新しいプリセットを追加 で必要なパターンを作成します。
  4. 各子GameObjectの プリセット名 と演出値を設定します。
  5. Controllerの プリセット一覧 に、使用順どおり登録されていることを確認します。
  6. 一覧が合わない場合は 一覧を子から自動検出 を押します。
  7. 選択番号をプレビュー適用 で各番号の内容を確認します。

関連設定

設定意味
ライブプリセットを使用OFFの場合、切替イベントを受けても何も変更しません。
開始時に選択中プリセットを適用World開始時に currentPresetIndex の内容を適用します。通常はONを推奨します。
プリセットの動作範囲切替を自分だけにするか、全プレイヤーへ同期するかを選びます。
選択プリセット番号ApplySelectedPreset が使用する番号です。Inspector上では0から入力します。
子GameObjectのHierarchy順とプリセット一覧の順番が常に自動連動するわけではありません。並べ替え後は「一覧を子から自動検出」とプレビューで番号を確認してください。

3. 使用できるCustom Event

イベント名動作引数
NextPreset次のプリセットへ進みます。末尾なら0へ戻ります。不要
PreviousPreset前のプリセットへ戻ります。0なら末尾へ移動します。不要
ReloadCurrentPreset現在選ばれているプリセットを再適用します。不要
ApplySelectedPresetpresetSelectionIndex の番号を適用します。事前に番号を設定
Custom Event名は大文字・小文字を区別します。空白や括弧を付けず、表の名前をそのまま使用してください。

SelectPreset(int) はController内部／UdonSharpから直接使用できる引数付きメソッドですが、文字列だけを送る通常のCustom Eventには引数を渡せません。汎用スイッチから番号指定する場合は presetSelectionIndex を設定してから ApplySelectedPreset を送ります。

4. 順送り・逆送りで切り替える

最も簡単で壊れにくい方法です。番号をスイッチ側に持たせる必要がありません。

次へボタン

対象：ControllerのUdonBehaviour

Event：NextPreset

例：0 → 1 → 2 → 0

前へボタン

対象：ControllerのUdonBehaviour

Event：PreviousPreset

例：0 → 2 → 1 → 0

  1. スイッチ用GameObjectを作成します。
  2. Colliderと、Interactを処理するUdonBehaviourを追加します。
  3. 送信先にMirrorBallLightControllerのUdonBehaviourを設定します。
  4. イベント名へ NextPreset または PreviousPreset を設定します。
  5. Play Modeで末尾から先頭へ正しくループすることを確認します。
複数のボタンを用意する場合でも、次へ／前へ方式ならプリセット数を増やした後にスイッチ設定を変更する必要がありません。

5. 特定番号へ直接切り替える

「赤」「青」「クラブ」など、パターンごとの専用ボタンを作る場合に使います。

presetSelectionIndex = 2→ApplySelectedPreset→一覧の3番目を適用

重要な順序

  1. Controllerの変数 presetSelectionIndex へ番号を設定する
  2. 同じControllerへ ApplySelectedPreset を送る

イベントだけを先に送ると、以前の番号または初期値0が適用されます。

範囲外の番号

Controllerは番号を有効範囲へ補正します。例えばプリセットが3個の場合、使用できる番号は0～2です。3以上を指定すると2へ、負数を指定すると0へ補正されます。ただし意図しないパターンになるため、スイッチ側の番号を正しく設定してください。

6. ワールド内の3Dスイッチ

3Dボタンは通常、Collider付きGameObjectの Interact() からControllerへイベントを送ります。

順送りスイッチ

  1. Cubeなどを作成し、Colliderを残します。
  2. Interact可能なUdonSharpBehaviourまたはUdon Graphを追加します。
  3. Controller参照を設定します。
  4. Interact時に NextPreset を送ります。
  5. 必要なら表示Textへ「次のパターン」と記載します。

番号指定スイッチ

各スイッチに番号を持たせ、Interact時にControllerの変数を設定してから適用イベントを送ります。具体的なコードは「8. UdonSharp例」を参照してください。

スイッチの反応範囲や操作可否はスイッチ側Udonの設定です。MirrorBall Controllerの「このオブジェクトをクリックして切替」は電源用なので、プリセットスイッチ側には使用しません。

7. Unity UI Buttonから切り替える

VRChatのUnity UI Buttonは、通常のC# MonoBehaviourを直接実行するのではなく、UdonBehaviourを経由してCustom Eventを送る構成にします。

  1. World Space CanvasへButtonを作成します。
  2. Buttonと同じ、または別GameObjectへ切替用UdonSharpBehaviourを追加します。
  3. Buttonの On Click() に切替用UdonBehaviourを登録します。
  4. 切替用Behaviourの公開イベントを選び、その中からControllerへ NextPreset などを送ります。
  5. VRChat UI入力に必要なCollider、VRC Ui Shape、Layer等をプロジェクト構成に合わせて設定します。
Unity UIのOn ClickへControllerの引数付き SelectPreset(int) を直接登録する構成は、Udon変換や同期を安定して通らない可能性があります。切替用UdonSharpBehaviourを経由する方式を推奨します。

8. UdonSharpスイッチ実装例

以下は別ファイルとして作成する最小例です。ファイル名とpublicクラス名を一致させてください。

次へ進むスイッチ

using UdonSharp;
using UnityEngine;

public class MirrorBallNextPresetSwitch : UdonSharpBehaviour
{
    public MirrorBallLightController controller;

    public override void Interact()
    {
        if (controller != null)
            controller.SendCustomEvent("NextPreset");
    }
}

番号を指定するスイッチ

using UdonSharp;
using UnityEngine;

public class MirrorBallPresetSelectSwitch : UdonSharpBehaviour
{
    public MirrorBallLightController controller;
    [Min(0)] public int presetIndex;

    public override void Interact()
    {
        if (controller == null) return;
        controller.presetSelectionIndex = presetIndex;
        controller.SendCustomEvent("ApplySelectedPreset");
    }
}

UdonBehaviour参照だけを使う汎用例

using UdonSharp;
using UnityEngine;
using VRC.Udon;

public class MirrorBallPresetGenericSwitch : UdonSharpBehaviour
{
    public UdonBehaviour controller;
    [Min(0)] public int presetIndex;

    public override void Interact()
    {
        if (controller == null) return;
        controller.SetProgramVariable("presetSelectionIndex", presetIndex);
        controller.SendCustomEvent("ApplySelectedPreset");
    }
}
同じ番号へ直接切り替えるだけなら、Controller型を参照する2番目の例が読みやすくなります。パッケージへの型依存を避けたい汎用スイッチでは3番目を使用できます。

9. Udon Graphで設定する場合

次へ進む

Event Interact→Send Custom Event→Target: Controller
Name: NextPreset

番号指定

Event Interact→Set Program Variable
presetSelectionIndex→Send Custom Event
ApplySelectedPreset

Set Program Variableの対象とSend Custom Eventの対象は、どちらも同じMirrorBall ControllerのUdonBehaviourです。変数名は presetSelectionIndex と完全一致させます。

番号設定とイベント送信の実行順を逆にしないでください。Graph上でフロー線を使い、Set Program Variableの完了後にSend Custom Eventへ進めます。

10. Local／Global切替の違い

プリセットの動作範囲結果通信
ローカル（自分だけ）操作した本人だけが選択した演出を見るなし
グローバル（全員に同期）選択番号を全員へ同期。途中参加者も同じ番号を復元Manual同期

Globalの処理

  1. 操作したプレイヤーがControllerのOwnerになります。
  2. currentPresetIndex が更新されます。
  3. 操作したプレイヤーへプリセットが即時適用されます。
  4. RequestSerialization() で番号を同期します。
  5. 他プレイヤーは受信後、同じ番号のローカルPreset値を適用します。
同期されるのはPresetの全数値ではなく選択番号です。全クライアントはアップロードされた同じWorldを使用するため通常は一致しますが、テスト中にクライアントごとに異なるSceneビルドを使うと表示が一致しません。

電源同期との関係

動作範囲は電源用、プリセットの動作範囲はPreset用です。別々に設定できます。

例電源プリセット
会場管理者が全員の演出を操作GlobalGlobal
電源は共有、演出は各自で選択GlobalLocal
個人用プレビューLocalLocal

11. 推奨テスト手順

Editorで内容を確認

  1. プリセット番号0を指定し、選択番号をプレビュー適用 を押します。
  2. 番号を1、2と変更し、色・光点・回転・透過面が意図どおり変わるか確認します。
  3. Texture形状のPresetではProject内Textureが設定されていることを確認します。

Play Mode／ClientSim

  1. NextPreset で末尾から0へループするか確認します。
  2. PreviousPreset で0から末尾へループするか確認します。
  3. 番号指定スイッチが0始まりで正しいPresetを選ぶか確認します。
  4. Local設定では他クライアントに影響しないことを確認します。
  5. Global設定では他クライアントと途中参加者が同じ番号になることを確認します。

アップロード前

  • ライブプリセットを使用＝ON
  • プリセット一覧にnullなし
  • 番号と表示名の対応を確認済み
  • スイッチのイベント名が完全一致
  • Global使用時は複数クライアントで確認済み
  • Consoleに赤いコンパイルエラーなし

12. 切り替わらない場合の確認

症状確認項目
何も変化しないライブプリセットを使用がONか／一覧が空でないか／対象Presetがnullでないか
常に最初のPresetになるpresetSelectionIndex をイベント送信前に設定しているか
1つずれたPresetになる番号は0始まり。画面上の1番目は番号0
次へ進むが途中で止まる一覧途中にnullがないか／イベント名が NextPreset か
自分だけ変わるプリセットの動作範囲をGlobalに設定したか
他プレイヤーと違うPresetになる一覧の数・順番が同じSceneビルドか／Global設定か
見た目が変わらない項目があるその値がMirrorBallLightPresetへ保存されている対象か／対象Materialが登録済みか
Texture形状だけ表示されないTextureがProject内アセットか／Presetの形状がTextureか／Texture参照が設定済みか
切替確認では、Presetごとの基本色や光点サイズを一時的に大きく変えると判別しやすくなります。動作確認後に本来の値へ戻してください。
