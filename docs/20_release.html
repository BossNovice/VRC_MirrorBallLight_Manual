困ったとき

診断と公開前チェック

診断ウィンドウの使い方と、VRChatへ公開する前に見る項目です。

診断・最適化ウィンドウの使い方

参照、Material、Shaderキーワード、Material個別のAudioLink設定、ライブプリセット、Texture Import設定、Global共有の競合をまとめて確認します。

開く

どちらからでも同じウィンドウが開きます。

  • Unityのメニューから Tools > MirrorBall Light > 診断・最適化
  • ControllerのInspectorの「10. 最適化・診断」にある「診断・最適化ウィンドウを開く」

使う順番

  1. 先にSceneとMaterialを保存します。 自動修正はMaterialを書き換えます。戻せるようにしてから実行してください。
  2. 「再診断」を押します。開いたままシーンを触った後は、押し直さないと表示が古いままです。
  3. 上部の「エラー: n　警告: n」を見ます。エラーが1件でもあると、この状態ではBuildが止まります。
  4. 直せるものは「安全に自動修正」で直します。触るのはMaterialとTexture Import設定だけです。Hierarchyの参照や電源などの設定値は書き換えません。
  5. 修正後にConsoleと実際の見た目を確かめます。自動修正で直らなかった項目は、一覧に残ります。

誰かに見てもらうとき

一覧の内容はそのままテキストにできます。

  1. 「レポートに Hierarchy のパスを含める（自分用）」のチェックを外します。 パスにはワールドの構造が出るためです。
  2. 「レポートをコピー」を押します。クリップボードへ入り、Consoleにも記録が残ります。
  3. そのまま貼り付けて渡します。
自分用に残す場合はチェックを入れたままにします。どのオブジェクトのことかがパスで分かるようになります。

Controllerの10. 最適化・診断

表示名 初期値 効果
Shader Global共有を使用（推奨） ON 共通パラメーターをMaterialごとではなく一度だけ更新します。同一シーンのGlobal共有Controllerは1個だけにします。
投影回転をGPUで計算（推奨） ON 回転によるMaterial更新をGPUへ移します。Global共有ON時のみ有効です。
表示用ミラーボール本体も回転 ON 投影だけでなく実際のTransformも回転します。
マテリアル更新頻度（回/秒） 30 / 10–90 動的値の更新上限。低いほどCPU負荷が下がり、高いほどフェードが滑らかです。
プリセット差分更新の最小値 0.001 クロスフェード中の微小な更新を省略する閾値。大きいほど軽量ですが段差が出やすくなります。

「診断・最適化ウィンドウを開く」から構成検査と推奨修正を実行できます。

設定の矛盾を先に潰す

Tools > MirrorBall Light > 診断・最適化 を実行してください。負荷に関係する項目も知らせます。

  • 更新頻度 × 対象Material数が大きすぎる場合の警告
  • Shader Global共有が有効なControllerが複数ある場合のエラー
  • 機能をONにしたのに必要なものが設定されていない組み合わせ

この画面が出す負荷のしきい値は経験的な目安であり、実機で計測した値ではありません。参考として使ってください。

VRChat公開前チェックリスト

  • Consoleの赤エラー0件
  • 「診断・最適化」のエラー0件（1件でもあるとBuildが止まります）
  • AudioLinkテストモードOFF
  • 使用モードと本体／Surface Materialが一致
  • TextureとCubemapがAssets配下
  • Material自動検出後に設定反映・保存
  • 個別AudioLinkマスク／発光パターン使用時は「診断・最適化」でKeyword整合を確認
  • Atlasシード自動フェード使用時は「診断・最適化」で _MB_ATLAS_SEED_FADE が自動同期されることを確認
  • Global共有Controllerが1個
  • Realtime Lightは1灯・影なし・必要範囲だけ
  • ClientSimで電源、同期、プリセット、透過面を確認
  • Build & TestしたVRChatクライアントで形状とAudioLinkを確認
