LTCGI・VRCLightVolumes連携

連携版Shaderの使い方と、アバターへ実際の光を当てる方法です。

通常版と連携版

バージョンを組で揃えてください。 VRCLightVolumes 2.xにはLTCGI 1.7.2、VRCLV 3.0.0-dev.14以降にはLTCGI 1.7.3以降を使用します。VRCLV 3.0.0-dev.12／dev.13はLTCGI非互換です。
MirrorBallLightより先に導入してください。 連携版Shaderは Packages/red.sim.lightvolumes/Shaders/LightVolumes.cginc と Packages/at.pimaker.ltcgi/Shaders/LTCGI_structs.cginc を直接includeするため、後から導入するとImport時にShaderのコンパイルエラーが出ます。
Tools > MirrorBall Light > 診断・最適化 が最初の行で依存Packageの有無とバージョンを表示します。未導入の場合は原因と対処も表示します。
モード 本体 Surface Material
通常版 MirrorBallFacetBody 名前が_Standardで終わる付属Material
LTCGI・VRCLightVolumes版 MirrorBallFacetBody (VRCLightVolumes + LTCGI) 名前が_LTCGI_LightVolumesで終わる付属Material

Controllerの「本体表示モード」は本体球だけを切り替えます。壁・床・ガラスのMaterialは自動差し替えされないため、使用モードに合うMaterialを割り当てます。

コンパイル確認と実機での見え方は別のものです。 コンパイル確認はUdonSharpの変換とShaderのコンパイルにエラーが出ないことを見たもので、実機目視は代表的なシーンを見たものです。どちらも全機能を網羅した確認ではありません。

受理する範囲は3.0系全体です。 上流がdev.15からdev.16へ動いたときに、こちらが何も変えていないのに検査が止まるのを避けるためです。範囲を広く取っているのは検査の都合であって、その範囲の全部を確かめたという意味ではありません。
表にない組み合わせは確かめていません。 「問題が無いことを確認した」という意味ではありません。VRCLightVolumes 2.xとLTCGI 1.7.3のような組み替えは、上の「バージョンを組で揃えてください」に反します。

VRCLightVolumes

連携Shaderの「VRCLightVolumesを使用」はLight Volumeからの照明をSurface／本体へ反映するKeywordです。Controllerの「すべてON」で対応MaterialのKeywordも同時に設定します。

  1. VRC Light Volumesをプロジェクトへ導入します。
  2. シーンへ必要なLight Volume Manager／Volumeを配置してBakeまたは設定します。
  3. 連携Materialを対象Rendererへ割り当てます。
  4. Controllerの本体表示モードを連携版へ変更します。
  5. 9番の「すべてON」を押し、設定を保存します。
「VRCLightVolumes用オブジェクト」はMaterialのToggleとは別で、アバター向けDynamic Volume等のGameObjectを電源連動させる参照です。

ワールド法線の反映

VRCLightVolumes 3.x環境では、LightVolumeSHへワールド法線を渡すようになり、法線方向に応じたライト・シャドウ評価が通常面・透過面・本体ファセットへ反映されます。曲面や斜面での陰影がより自然になりますが、Material設定や導入手順に変更はありません。VRCLightVolumes 2.x環境では従来の5引数APIのまま動作するため、導入側で意識する必要はありません。

LTCGI

LTCGI側で対象Rendererを登録し、LTCGIの手順に従ってBake／Updateします。ControllerのONだけではLTCGIデータそのものは生成されません。

アバターへの実光

Realtime Light方式

ControllerへPoint Lightを1灯割り当てます。「安全設定」ボタンでRealtime、影なしへ設定し、Rangeを必要最小限にします。PC向けで、ワールド全体のRealtime Light数に注意します。

VRCLightVolumes方式

DynamicなPoint Light Volumeを別の子GameObjectとして構成し、「VRCLightVolumes用オブジェクト」へ指定します。Controllerは電源フェードに合わせてGameObjectの有効状態を管理します。

Realtime LightとVolumeを両方強くすると二重に明るく見える可能性があります。片方ずつ確認し、必要な分だけ併用してください。

Controller側の設定

表示名 初期値 効果
アバター用リアルタイムライト（任意） なし アバターへ当たるPC向けRealtime Light。負荷のため1灯・影なし推奨です。
VRCLightVolumes用オブジェクト（任意） なし 電源と連動してActiveを切り替える別の子GameObjectです。Controller自身は指定不可です。
アバター用ライトの明るさ 1.5 / 0–10 Realtime Lightの基準Intensityです。
アバター用ライトの範囲 8 / 0.1–30 Realtime LightのRangeです。広げすぎると影響範囲と負荷が増えます。
反射光の色を使用 ON ONはControllerの基本色、OFFはLight側の色を維持します。
AudioLink入力AudioSource（任意） なし アバター実光の音量解析元です。壁ShaderのAudioLink入力とは別です。
アバターライトの反応帯域 0 / 0–3 実光の音連動に使う周波数帯を選びます。
アバター用ライトの音連動量 0.5 / 0–2 AudioSource解析結果によるIntensity増加量です。

「アバター用ライトを安全設定」はPoint／Realtime／影なしへ整えます。詳細はアバターへの実光を参照してください。

Controllerの「すべてON／すべてOFF」

「すべてON／すべてOFF」は、対象Materialと本体Materialのうち_LightVolumes／_LTCGIを持つものだけを一括変更し、Material Assetへ保存します。通常版Materialには影響しません。

設定済みサンプルを連携版へ変更

  1. LTCGIとVRC Light Volumesを先に導入します。
  2. Controllerの「本体表示モード」を「LTCGI・VRCLightVolumes版」へ変更します。
  3. mirrorball_light_wallへReflectionSurface_LTCGI_LightVolumesを割り当てます。
  4. 「対象マテリアルをシーンから自動検出」を実行します。
  5. 「すべてON」と「現在の設定をマテリアルへ反映・保存」を押します。
  6. 各連携パッケージ側のシーン設定を完了します。
