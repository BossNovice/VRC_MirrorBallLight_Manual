自分の壁・床へ適用する

使うShaderを選び、Materialを割り当てて、Controllerへ登録するまでです。

自分の壁へ適用する

  1. 対象壁のMaterialを複製します。
  2. 通常の壁ならMirrorBallLight/MirrorBallSurfaceAuto、ガラスならMirrorBallLight/MirrorBallSurfaceAutoTransparentへ変更します。
  3. 元のBase Texture、Color、Normal Mapなどを移します。
  4. Controllerの「対象マテリアルをシーンから自動検出」を押します。
  5. 「現在の設定をマテリアルへ反映・保存」を押します。
付属Materialを直接編集すると、サンプルと統合Prefabの見た目にも共有されます。ワールド固有の調整ではMaterialを複製してください。

MaterialのInspectorの使い方

MirrorBallLightのSurface Shaderを割り当てたMaterialは、項目が11個の折りたたみに分かれて表示されます。 Unity標準のMaterial表示とは並びが違います。

Shaderを割り当てる

  1. ProjectウィンドウでMaterialを選びます。1つのMaterialを複数のRendererで共有していると、直した見た目はその全部に反映されます。 片方だけ変えたいなら、先に複製して割り当て直してください。付属Materialをそのまま編集するのも避けてください。 サンプルと統合Prefabの見た目も一緒に変わります。Ctrl+D で複製してから使います。
  2. Inspector上部の Shader のドロップダウンを開きます。
  3. 通常の壁・床なら MirrorBallLight/MirrorBallSurfaceAuto、ガラスなど透過するものなら MirrorBallLight/MirrorBallSurfaceAutoTransparent を選びます。
  4. 元のTexture・色・Normal Mapを、新しい項目へ入れ直します。既存Materialからまとめて移したい場合はMaterial変換を使います。

上にある「すべて開く」「すべて閉じる」でまとめて操作できます。

Controllerが書き込む項目を手で変えても、次にControllerが反映したときに上書きされます。 どちらが正かは「Controller連動とMaterial直編集」を参照してください。Materialごとに決めたい設定（2番・6番など）は上書きされません。

遮蔽キューブマップで遮蔽物の裏に光点を出さない

受光面Shaderの光点はそのままに、柱・カウンター・梁の裏に光点が出ないようにする機能です。ボールの中心から見た最寄りの面までの距離を6面ぶん（+X・-X・+Y・-Y・+Z・-Z）、縦に並べた1枚のテクスチャへ焼いておき、受光面Shaderが画素までの距離と比べて、手前に遮蔽物があれば光点を描きません。光点の配置・大きさ・形・回転は変わらず、遮蔽の縁は画素単位で切れます。既定ではOFFで、焼いて初めて効きます。

焼き方

  1. Sceneを保存し、Controllerのミラーボール mirrorBall を設定します。遮蔽物（柱・カウンター・梁・壁）が最終の位置にあることを確かめます。
  2. Tools → MirrorBall Light → 遮蔽キューブマップを焼くを開き、Controllerを指定します。Controllerの「8. 高度な投影・Sceneプレビュー」の遮蔽キューブマップを焼く…と、導入セットアップの「3. 動作の確認」からも開けます。
  3. 焼く遮蔽物のLayerで、遮蔽物のあるLayerを選びます（既定はすべて）。焼く解像度は128／256／512（既定）px/面です。512 は RHalf で約3MB です。取り付け具など、自動で除外されない物があれば焼くときに除外する物へ入れます。
  4. 焼く対象を確認で、焼く遮蔽物の数と除外の内訳を見ます。
  5. 焼いて Controller に設定を押します。キューブマップは Assets/MirrorBallLight/Generated/Occlusion/ に保存され（RHalf、6面を縦に並べた1枚のテクスチャ）、Controllerの遮蔽キューブマップ（6面アトラス）に入り、遮蔽キューブマップを使用がONになります。結果欄とConsoleに、遮蔽物の数・除外の内訳・軸方向6本の照合が出ます。Undoで戻せます。

表示例です。

「遮蔽キューブマップを焼きました: Assets/MirrorBallLight/Generated/Occlusion/World_MirrorBallLight_Occlusion.asset（256 px/面、RHalf）。遮蔽物 48個
除外 ミラーボール本体・取り付け具（本体とControllerの階層、本体に触れている物、除外に指定した物）：3個
除外 動く物（Pickup・ObjectSync・動くRigidbody・SkinnedMesh）：2個
除外 半透明・透過（Render Queue 3000以上、受光面の透過版Shader）：4個
軸方向6本の照合: 5/6 一致（Collider と描画Meshが違う物は一致しません。参考値です）。」

焼かない物

除外の理由判定
判定の順は、半透明・透過 → 動く物 → EditorOnly → LayerMaskの外 → 本体の階層と除外に指定した物 → 本体に触れている物です。ボールを囲む半透明の箱は「半透明・透過」として除外されます。
ミラーボール本体・取り付け具本体とControllerの階層、本体に触れている物、焼くときに除外する物に指定した物とその子。自分で自分を遮らないためです。「本体に触れている」は、ボールの中心（本体の Transform の位置。受光面Shaderと焼きも同じ点を中心に使います）から相手の実際の表面までの距離が、球の半径（本体の階層のRendererを合わせた外形の箱のいちばん短い辺の半分。吊り棒や鎖が本体のメッシュに含まれていても球の半径のままです）の1.25倍＋5cm以内のことです。表面までの距離は Collider（Box・Sphere・Capsule・凸のMesh）に聞き、答えられる Collider が無ければメッシュの頂点までの距離で見ます。壁・床・天井を1つにまとめた部屋の殻や、ボールを囲む箱のように中心を含む物は、囲んでいるだけとみなして遮蔽物に残します。ボールから離れた吊り金具・トラス・梁は遮蔽物に入ります（実物でも光を遮ります）。入れたくなければ焼くときに除外する物に指定してください。本体の Transform の位置がボールの中心でない構成（ピボットが吊り棒の上端など）は、受光面Shaderの光点もずれるので、先に本体の位置をボールの中心に合わせてください
動く物自身か親に VRC Pickup・VRC Object Sync・Kinematic でない Rigidbody がある物、SkinnedMeshRenderer
半透明・透過Materialの Render Queue が3000以上、または受光面の透過版Shader（ガラス・貼り紙の板ポリは遮蔽物にしません）
EditorOnlyタグ自身か親に EditorOnly タグがある（ビルドで消える物）
LayerMaskの外焼く遮蔽物のLayerに入っていないLayer
メッシュ以外のRendererパーティクル・ライン・トレイルなど

調整

  • 遮蔽キューブマップを使用：ON／OFF。キューブマップが無いときは効きません（診断 MBL-W034）。
  • 距離の許容幅（m）と距離1mあたりの許容幅（既定 0.03 と 0.01）：受光面自身を遮蔽物とみなさないための幅です。焼いた距離が「画素までの距離 − 許容幅」より手前のときだけ遮ります。斜め・曲面の受光面や、別の遮蔽物の縁の横で光点が削られる症状は、許容幅ではなく下の「縁の判定」で直ります。
  • 縁の判定：受光面の画素ごとに、ボールから見た方向のテクセルをどう引くかです。保守的な2×2（既定）は、画素の方向を囲む4つのテクセルのうち1つでも遮蔽物より手前なら見えるとします。テクセルの中心の方向だけ別の遮蔽物の縁に当たっている場合や、ソファの背もたれ・円柱のように寝た受光面でも、光点を削りません（R37.3・R37.4 では縁の段々や縞に削れていました）。代わりに遮蔽物の縁が最大1テクセル分内側へ縮みます（512 px/面で 3m 先 1.2cm、256 px/面で 2.3cm の光漏れ。幅1テクセル未満の細い物は遮りにくくなります）。1タップは R37.3・R37.4 の判定で、縁は硬いテクセルの段になります。4タップ平均は縁を0.25刻みの中間にして和らげます。どれも画素ごとにアトラスを1回（1タップ）か4回引きます。ボールから見た6面の継ぎ目から半テクセルの帯は、保守的な2×2でも1タップに近い判定になります。
  • Shader Global共有がONでもOFFでも、効くのはControllerの遮蔽キューブマップだけです。Material側に別のキューブマップが入っていると診断 MBL-W037 が出ます。

制限と焼き直し

  • 静的な遮蔽物だけが対象です。 アバター・Pickup・動く物・開閉するドアは遮りません。半透明の物は遮蔽物にしません。
  • ボールが動く構成は対象外です。 キューブマップはボールの中心から見た距離なので、ボールを動かすと合わなくなります。焼いた後にボールが1cm以上動くと、診断に MBL-W035 が出ます。
  • 柱や家具を動かした・増やした・消したときは焼き直してください。焼く対象の遮蔽物の数・位置・向き・大きさ・Meshが変わると、診断に MBL-W036 が出ます。警告だけで、自動では焼き直しません。
  • R37.3・R37.4 で焼いたシーンは焼き直してください。診断に MBL-W038 が出ます。R37.3 は部屋の殻（外形の箱がボールを含む物）を取り付け具として除外し、何にも当たらない向きを Infinity で焼いていました。R37.4 は本体の外形の箱に近いだけの物（吊り棒を含む本体の近くの梁・トラックライト）を取り付け具として除外していました。焼き直すと、これらが遮蔽物に入り、「焼く対象を確認」の内訳が変わります。
  • 焼いたときの状態は Controller に残ります（occlusionBakedBallPosition・occlusionBakedSceneHash）。Prefab にして別の Scene へ置くときは、置いた先で焼き直してください。
  • Lighting Engineと併用できますが、Engineの光点はEngine自身がRaycastで遮蔽を判定し、キューブマップは使いません。

Lighting Engineで実形状へ反射を配置する

壁・床・天井へ球面Facetの反射方向から光点を配置する機能です。既定の受光面Shaderによる描画とは別の経路で、使うときだけ導入します。

Engineの光点はスポットライトからの反射を実際に追うので、見た目は物理反射になります。光源がボールの真上（回転軸上）に無いと、光点の回転の中心は光源の反対側へ「光源の水平ずれ×（天井の高さ÷光源の高さ）」だけずれ、軌跡も円ではなく歪みます（実物のミラーボールと同じ）。受光面Shaderの光点は光源の位置を使わず、常にボールの真上を中心に回ります。既存の見た目のまま、遮蔽物の裏に光点を出したくないだけなら、遮蔽キューブマップを使ってください。

  1. Sceneを保存し、Controllerのミラーボール mirrorBall と入射Spot Light spotLight を設定します。Spotの向き・角度・範囲がボールへ届くことを確認します。
  2. Tools → MirrorBall Light → Lighting Engineを導入を開き、Controllerと受光対象の階層を指定します。対象を検出・適用内容を確認を押します。
  3. 一覧の対象チェックとFloor／Wall／Ceiling／Stage／Objects／Avatar分類を見直します。自動分類は候補なので、ステージなどは手動で訂正します。AvatarはSceneに配置したモデルのみです。実行時に参加するプレイヤーAvatarは登録対象に含めません。鏡・動画スクリーン・テキスト・半透明のMaterialは最初からチェックが外れています（自動で除外される対象）。
  4. 必要なMeshColliderを追加を選ぶと、足りない対象へ実形状のColliderを追加します。有効な非Trigger Colliderが必要です。共有する親Colliderを異なるグループへ分類すると競合するため、一覧を整理してから一覧の対象へLighting Engineを設定を押します。適用はUndoで戻せます。
  5. 追加された MirrorBallLightingEngine の controller／receiverManager／ball／incomingSpot を確認します。Setupが作る spotMesh はローカルXY平面・法線+ZのQuad、spotMaterial は MirrorBallLight/InstancedSpot とGPU Instancing有効の組み合わせです。ボールのFacet法線・中心と、登録した対象ごとの受光面の色もSetupで用意します（下記）。シーンにAudioLinkがあれば audioLinkBehaviour へつなぎます（下記）。
  6. raycastLayers にはReceiverだけでなく、反射を止める登録外の柱・家具・壁も含めます。最初に当たったColliderが未登録なら、その方向の光点を出しません。遮蔽物をLayerMaskから外すと光が通り抜けます。maximumRayDistance とSpot角度も実際の部屋に合わせます。

自動で除外される対象

対象を検出・適用内容を確認を押すと、次のRendererはチェックが外れた状態で一覧に出ます。

一覧に出る理由判定
鏡（VRC Mirror）自身か親に VRCMirrorReflection がある
動画スクリーン（VideoPlayer・VRC動画プレイヤー）自身・親・子に VideoPlayer かVRChatの動画プレイヤーがある、または VRCAVProVideoScreen がある
テキスト（TextMesh・TextMeshPro）TextMesh か TextMeshPro がある
半透明・加算のMaterial（Render Queue 3000以上）1つ目のMaterialのRender Queueが3000以上

除外の件数は、検出時と適用後の結果欄に理由ごとに出ます。表示例です。

「3個のRendererを登録対象にしました。分類と除外対象を確認してから適用できます。

除外 テキスト（TextMesh・TextMeshPro）：2個

ボールのFacet選別

Setupはボールのメッシュへ球を当てはめ、その球面上にある外向きの三角形だけを反射Facetとして焼き込みます。同じメッシュに入った鎖や吊り金具の三角形はFacetにしません。面積0の三角形も除外します。主に球でない形状は、すべての三角形をFacetにします。

Facetの上限は8192個です。超える場合は球面全体から均等に間引きます。結果欄には反射Facet数・ボールMeshの三角形数・除外数が出ます。表示例です。

「反射Facet 8192個を登録。ボールMeshの三角形 17156個のうち、鎖など球面から外れた三角形・面積0の三角形 508個を除外しました。上限8192個まで均等に間引いています。」

最後の「上限8192個まで均等に間引いています。」は間引いたときだけ出ます。ボールにMeshがない場合は「ボールのMesh（三角形）がないため、実行時に球面のFacetを自動生成します。」と出ます。

受光面の色

Engineの光点は、当たった面のMaterialの色を掛けて描きます。暗いMaterialでは光点が暗くなり、色の付いたMaterialでは光点にその色が付きます。白いMaterialでは光点の色は変わりません。シーンのライティングには左右されません。

色は一覧の対象へLighting Engineを設定を押したときに、登録するRendererごとに記録します。記録するのは、1つ目のMaterialの _Color と、メッシュが実際に使うUV範囲のメインテクスチャの平均を掛けた色です。_Color が無いShaderは白として扱います。2つ目以降のMaterialは使いません。テクスチャやメッシュのRead/WriteがOFFでも測れます。Materialやテクスチャを変えたら、もう一度押して記録し直します。

テクスチャはGPUで読むため、グラフィックスありのEditorが必要です。読めない環境では何も変更せずに止まり、「受光面の色を測れません：GPUでのテクスチャ読み出し（RGBA Half の ReadPixels）が使えません。グラフィックスありのEditorで実行してください。」と出ます。

効き具合はEngine Inspectorの受光面の色の影響（receiverColorInfluence、0〜1、既定1）で決めます。1で面の色をそのまま掛け、0では面の色を使わない白い光点になります。用途別プリセットと演出Assetはこの値を変えません。

色を記録していない登録対象があると、Engine Inspectorに次の警告が出ます。色の記録が入る前に導入したシーンでも出ます。その対象の光点は白で描かれます。

「受光面の色が未登録の対象があります（白で表示されます）。受光対象の登録を開き、「一覧の対象へLighting Engineを設定」をもう一度実行してください。」

光点の形状

Engineの光点は、Controllerの光点の形状で描きます。内蔵の形状（四角・丸・ひし形・十字・六角形・星・リング・ハート）、光点形状テクスチャ、複数形状アトラスを使用のどれも、受光面Shaderの光点と同じように使えます。アトラスでは光点ごとに形状が決まり、その光点が消えるまで変わりません。Controllerの形状を変えると、実行中のEngineの光点も変わります。

光点の形状の既定は「四角」なので、Engineの光点も既定では四角です。丸い光点にするには、Controllerで「丸」を選び、複数形状アトラスを使用をOFFにします。受光面Shaderの光点も同じ形になります。形状が「丸」以外か、アトラスを使っているときは、Engine Inspectorに次の案内が出ます。

「反射光点はControllerの「光点の形状」（形状テクスチャ・複数形状アトラス・光点アンチエイリアスを含む）で描かれます。丸い光点にするには、Controllerの「光点の形状」を「丸」にし、「複数形状アトラスを使用」をOFFにしてください（Controllerの受光面の光点も同じ形になります）。」

Controllerの光点アンチエイリアスは、Engineの内蔵形状では輪郭をぼかす幅として効きます。0で約1画素、1で約2画素です。形状テクスチャとアトラスの輪郭はテクスチャのままです。内蔵形状には、Engineの spotSoftness による内側のぼかしも掛かります。

R37.1から、Engineの光点も受光面Shaderの光点と同じように、斜めの面では入射の方向へ伸びます。面の法線と反射の向きのなす角をθとすると、反射の向きを面へ投影した方向に 1÷cosθ 倍（上限6倍、約80°）伸び、形状テクスチャや形状アトラスの形も一緒に伸びます。伸びた分だけ面の明るさは薄くなり、面へ届く光の量は変わりません。伸びた光点は、当たった受光面の範囲で切れて、空中にははみ出しません。

光点の動きと制限

R37から、Engineの光点はボールと一緒に回り、壁・天井・床の上を流れます。光点はそれぞれ1枚のFacetを受け持ち、Rayで撃ち直すたびに同じFacetを確かめます。撃ち直しの合間は、そのフレームのボールの向きでFacetの反射を計算し直し、前に当たった面の上で光点を動かします。Facetが光を受けなくなったとき（裏を向いた、スポットライトの円錐から出た、遮られた）や、反射が受光面から外れたときに、その光点は消え、別のFacetを受け持ちます。新しく受け持った光点は短く（0.15秒）フェードインします。

R36.1までは、撃ち直すたびに別のFacetへ入れ替わる作りでした。光点は置かれた場所に止まったまま、約1秒に1回、別の場所へ跳んで見えました。

次の点は仕様です。

  • 光点を出すのは、ボール全体から均等に選んだ一部のFacetです（R37.1から）。 光点の数（品質ごとの上限）より照らされているFacetが多いときは、照らされる数が上限の約85%×光点の密度（Spot Density）になるよう、決まった一部のFacetだけを選びます。選ばれたFacetは光に入ったときに光点になり、光から出るまで流れます。光点は照らされた範囲に均等に散り、数は上限より少し少なくなります（光に入ってくるFacetのための空き）。光点を増やすには、ローカル品質か光点の密度を上げます。隣どうしの光点が3m先で重なるほど細かくは選びません。
  • R37.1より前に導入したシーンは、受光対象の登録を開き、「一覧の対象へLighting Engineを設定」をもう一度実行してください。 Facetを均等に選べる並びに焼き直します。実行するまでは、Engine Inspectorに警告が出て、光点がボールの一部に偏ることがあります。
  • 受光面は静止している前提です。 動く受光面や動く遮蔽物では、撃ち直すまで光点が古い位置の面に沿って動きます。
  • 曲面や凹凸のある面では、面の延長と実際に当たる位置が少しずれるため、撃ち直したときに光点が小さく動きます。
  • 入射角による伸びと明るさ、距離による大きさは、撃ち直しの合間もボールの向きに合わせて変わります（大きさはR37.2から）。
  • 撃ち直しの合間に面の端を越えた光点は、当たった面の範囲から出た時点で消えます。次に撃ち直したとき、隣の面に当たれば、そこへ移ります。

光点の大きさ

R37.2から、Engineの光点の直径は「鏡面1枚の大きさ＋ボールの中心からの距離×光点の角度」です。実際のミラーボールや受光面Shaderの光点と同じく、ボールに近い面では小さく、遠い面では大きくなります。

  • 既定では、Controllerの「光点の大きさ」とタイル数に合わせます（useControllerSpotSize）。受光面Shaderの光点は、ボールから見た方向の1マスの「光点の大きさ」倍の角度に広がります。Engineも同じ角度を使うので、同じ値で両方式の光点が同じ距離で同じ大きさになります。
  • useControllerSpotSize をOFFにすると、Engineの spotAngleDegrees（度）を使います。用途別プリセットは、この角度を設定します（「3m先で前の版と同じ直径」になる値）。
  • 鏡面1枚の大きさは、ボールの半径と鏡面の数から求めます。低音（Bass）で光点が大きくなる演出は、この直径に掛かります。
  • EngineのInspectorに、1m・3m・5m先での直径を表示します。
  • R37.2より前に導入したシーンでは、前の版の Spot Diameter・Beam Divergence は使われません。 EngineのInspectorに警告が出るので、表示される直径を見て、必要ならControllerの「光点の大きさ」か spotAngleDegrees で調整し、「光点の大きさを確認した」を押してください。

面の縁で切る（深度で切る）

光点が当たった面より大きいとき（細い梁、柱の角、段差、家具の縁）、はみ出した部分を描かないようにします。

  • 深度で切る（useDepthClip、R37.2から既定ON）：Engineが画面のカメラに深度テクスチャを作らせ（VRChatの VRCCameraSettings の公式の機能）、光点のうち実際の面から外れた画素を描きません。梁・柱の角・段差・家具の縁のどれでも、面の形どおりに切れます。撮影カメラ（Photo Mode）は常に深度があります。
  • 深度を使わないとき（useDepthClip がOFF、鏡の中）：当たったColliderの範囲で切ります。BoxColliderなら当たった面の範囲で切るので、BoxColliderの梁は梁の縁で切れます。それ以外のColliderは、Collider全体を囲む箱で切ります。
  • 確認用に debugClipPath をONにすると、深度で切っている光点は緑、Colliderの範囲で切っている光点は黄色で表示されます。実機でどちらの切り方になっているかを確かめるのに使い、確認が済んだらOFFに戻してください。

次の点は制限です。

  • 深度を使わないとき、MeshColliderはCollider全体を囲む箱で切ります。梁と天井、または何本もの梁を1つのMeshColliderにまとめていると、その箱の中にある梁と梁の間の空間に光点が浮きます（R37.1までの見え方）。梁のような細い受光対象は、1本ずつBoxColliderを付けた別のオブジェクトに分けてください。
  • 鏡の中は斜めの投影で深度が当てにならないため、深度で切らずにColliderの範囲で切ります。
  • アバターのカメラ（VRCLens・配信用カメラなど）は、VRChatの仕様で、画面のカメラが前に描いた深度を使います。そのカメラの画では、光点が欠けたり、切れなかったりすることがあります。
  • 画面のカメラに深度テクスチャを作らせると、不透明物の深度を描く処理が1回増えます。重さが気になるときは useDepthClip をOFFにしてください（Colliderの範囲で切ります）。一度要求した深度テクスチャは、そのインスタンスにいる間は残ります（ワールドの他の効果が使っている場合があるため、外しません）。
  • VR（両眼を1回で描く方式）での深度の読み方は、Shaderは両眼用の書き方ですが、実機ではまだ確認していません。

AudioLinkの自動接続

Setupは、programの名前が「AudioLink」のUdonBehaviourをシーンから探し、Engineの audioLinkBehaviour へ設定して requestAudioLinkReadback を有効にします。すでに audioLinkBehaviour を設定している場合は変更しません。見つからない場合は何も設定しません。あとからAudioLinkを置いたときは、もう一度一覧の対象へLighting Engineを設定を押すか、手で設定してください。詳しくはEngineの帯域反応を参照してください。

Receiver Managerの receiveFloor／receiveWalls／receiveCeiling／receiveStage／receiveObjects／receiveAvatars でグループを選び、各 *Intensity で強さを調整します。Avatarは既定で無効です。登録はEditorで焼き込み、実行中のScene全体の自動探索や既存Materialの置換は行いません。階層・Colliderを変えたら一覧から再登録してください。

engineEnabled を有効にすると別描画の反射を使い、受光面Shader側の反射と重ねて二重に表示しないようControllerへ通知します。Unityで engineEnabled をOFFにすると、従来の受光面Shaderの光点に戻ります。Engineの設定と登録した受光対象はそのまま残るので、ONに戻せば元のEngineの光点になります。回転設定・品質は回転と負荷調整を参照してください。
